# 근태 기능 변경 작업 매뉴얼

근태 기능은 화면 문구만 바꾸지 않고 데이터, 권한, 변경이력, 운영 DB까지 한 흐름으로 점검한다.

## 작업 순서

1. 사용자가 실제로 거치는 순서를 사례로 적는다.
2. 화면 상태와 DB 상태를 구분한다.
3. 기존 기록을 삭제하거나 의미를 덮어쓰지 않는 보완 방식을 우선한다.
4. 상태를 바꾸는 모든 작업은 변경이력의 작업명, 변경 전후 값, 처리자, 사유를 함께 설계한다.
5. 일부 정보만 수정할 때 이미 확인된 다른 항목까지 다시 확인 대상으로 만들지 않는다.
6. 월 마감, 기관 범위, 관리자 권한, 사용한 휴가·대휴 잔액을 함께 검증한다.
7. 별도 보완 SQL과 `supabase/install_current.sql`을 같은 내용으로 갱신한다.
8. 화면 검사, TypeScript 검사, 전체 자동검사, 배포 빌드를 실행한다.
9. 개인 저장소 커밋·푸시, 기관 저장소 동기화 PR·병합, 운영 DB SQL 적용, 운영 화면 확인을 각각 구분해 보고한다.

## 관리자 확인 기능 점검표

- 확인 필요 화면에 무엇을 확인해야 하는지 표시했는가?
- 직출, 직퇴, 위치 정확도, 출퇴근 누락, 지각, 근무시간 부족을 구분했는가?
- 출근정보 변경은 직출 확인만, 퇴근정보 변경은 직퇴·근무시간 확인만 무효화하는가?
- 관리자 확인 항목과 의견이 변경이력에 사람이 읽을 수 있는 문장으로 남는가?
- 이미 확인한 항목이 새로고침이나 무관한 수정으로 되돌아가지 않는가?
